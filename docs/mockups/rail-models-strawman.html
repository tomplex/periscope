Three ways periscope could organize your work

Same work in all three rails — your real-ish stuff: a big attribute-config effort spanning two fdy branches, the periscope home-base, and a branchless splash research task. What differs is the model, not the styling. The unit is an effort (a container of tabs); a tab is one claude or shell. Repo / branch / PR / ticket are attributes that decorate, they don't decide placement. tmux is just the terminal backend underneath — invisible here.

React to what's right and what's wrong. We converge, then I write the spec.

Model A

Flat efforts, named by goal

One flat list of efforts. You name them by intent ("attribute-config"), never by repo or branch. A branch is just a chip on the tab. The big effort, the home-base, and the one-off are identical in structure — they differ only in how many tabs they hold and how long they live. No nesting, ever.

  • You stop splitting work by branch. All attribute-config tabs sit together; the ⎇ chip tells you which branch each is on.
  • Opening a repo with no effort drops tabs into Inbox until you file them.
  • Repo becomes a chip + color, never a group.

Model B

Efforts with optional branch sub-clusters

An effort is the top unit, but inside a big one, tabs that share a branch tuck into a sub-cluster. Small efforts and the home-base stay flat — the sub-level only appears when an effort spans >1 branch. Closest to how you work today, but the effort is the parent (not the repo), and the branch sub-cluster is a convenience, not a tmux session.

  • Branch grouping survives, but only when it earns its keep (2+ branches).
  • Repo is a chip on the effort header, not a tier.
  • One-branch effort = flat. No more single-worktree double-headers.

Model C — fences swing

Attention first, effort is a chip

The rail's primary axis is what needs you, not where work lives. Every tab floats into a band by state — Needs you / Working / Done — across all efforts, each wearing its effort + repo as chips. Effort grouping still exists, but it's a collapsed browse strip at the bottom for jumping to/resuming work. Periscope is a monitor; this makes triage the default and structure the secondary view.

  • With 15 claudes running, you see who needs you now without hunting through groups.
  • Effort/repo become chips on every row; you can still filter to one.
  • "Browse by effort" is one click away when you want to start/resume, not monitor.
